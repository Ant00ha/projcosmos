# cosmo-A — проектирование устойчивой спутниковой группировки

Веб-сервис для проектирования спутниковой группировки и оценки доступности связи в северных районах. Позволяет загружать сценарии, редактировать конфигурацию, рассчитывать покрытие и маршруты передачи данных, сравнивать варианты и выгружать результаты.

## Быстрый старт

### Требования

- Python 3.10+
- pip

### Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### Запуск сервера

```bash
python -m uvicorn main:app --reload --port 8000
```

### Открыть в браузере

```
http://127.0.0.1:8000/
```

Для доступа с других устройств в локальной сети:

```bash
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

и открыть `http://<ваш-IP>:8000/`.

## Что умеет сервис

### 1. Сценарии

- Просмотр списка доступных сценариев.
- Загрузка пользовательского JSON. (в 5 пункте - загрузка своего JSON)
- Запуск расчёта на сутки с шагом 120 секунд.

### 2. Прогоны

- Сохранение результатов каждого расчёта.
- Просмотр метрик: видимость, доля маршрутов, максимальный перерыв.
- Экспорт `result_*.json` в формате `cosmo-A-result-1.0`.

### 3. Сравнение вариантов

- Diff по параметрам сценария.
- Diff по метрикам каждого наземного пункта.
- Diff по маршрутам: сколько изменилось, появилось, исчезло.
- Автоматическая рекомендация: какой вариант лучше и почему.

### 4. Таймлайн и диаграмма доступности

- Ползунок по 720 отсчётам (0…86 280 с).
- Диаграмма Гантта: зелёный — маршрут есть, красный — нет.
- Состояние сети в выбранный момент: активные спутники, видимые аппараты, маршрут до шлюза и причина его отсутствия.

### 5. Карта

- 2D-планисфера (равнопромежуточная цилиндрическая проекция).
- Спутники, окрашенные по состоянию (активен / не запущен / в отказе).
- Наземные пункты и шлюз.
- Межспутниковые связи (ISL) и наземные контакты.
- Маршрут выбранного клиента выделен жёлтым.

### 6. Редактирование сценария

- Выбор очереди запуска (1/2/3).
- Изменение RAAN и фазирования для каждой плоскости.
- Добавление / удаление периодов недоступности спутников.
- Изменение `isl_range_km` и `min_elevation_deg`.
- Сохранение как новый сценарий и запуск расчёта.

## Модель расчёта

### Константы

| Параметр | Значение |
|---|---|
| Радиус Земли R | 6371 км |
| Гравитационный параметр μ | 398600.435507 км³/с² |
| Период вращения Земли T | 86164.09054 с |
| Радиус орбиты r | R + h |
| Угловая скорость n | √(μ/r³) |

### Положение спутника

Для плоскости с RAAN Ω и наклонением i, при аргументе широты `u(t) = slot_deg + phase_deg + n·t`:

```
x = r·(cos Ω·cos u − sin Ω·sin u·cos i)
y = r·(sin Ω·cos u + cos Ω·sin u·cos i)
z = r·sin u·sin i
```

Переход в земную систему координат через `θ = earth_angle0_deg·π/180 + 2πt/T`:

```
xe = cos θ·x + sin θ·y
ye = −sin θ·x + cos θ·y
ze = z
```

### Наземные контакты

Угол возвышения для спутника `s` и наземного пункта `g`:

```
elev = arcsin( ((s−g)·g) / (||s−g||·R) )
```

Контакт доступен при `elev ≥ min_elevation_deg` и активном спутнике.

### Межспутниковые линии (ISL)

Контакт между спутниками `a` и `b` доступен, если:

- `||b − a|| < isl_range_km`;
- расстояние от центра Земли до отрезка `[a; b]` больше R.

Для проверки: `d = b − a`, `q = clip(−a·d / (d·d), 0, 1)`, ближайшая точка `a + q·d`.

### Маршрутизация

- BFS по числу переходов.
- Промежуточные узлы — только активные спутники.
- Старт — client, финиш — любой доступный gateway.
- При отсутствии маршрута определяется причина:
  - `no_visible_satellite` — нет видимого активного спутника;
  - `no_gateway_contact` — у шлюза нет видимого спутника;
  - `gateway_outage` — шлюз в периоде недоступности;
  - `isl_disconnected` — спутники видны, но ISL-сеть разорвана.

### Метрики по каждому наземному пункту

- Видимость — доля отсчётов с ≥1 видимым активным спутником.
- Путь до шлюза — доля отсчётов с найденным маршрутом.
- Максимальный перерыв — самая длинная серия отсчётов без маршрута × step_s.
- Число переходов — количество рёбер в маршруте (включая наземные).

## Результаты расчётов

| Сценарий | C65 путь | C70 путь | C72 путь | Цель 90% |
|---|---|---|---|---|
| `01_full_constellation` | 96.7% | 98.8% | 98.9% | достигнута |
| `02_first_launch` | 27.2% | 15.8% | 12.6% | не достигнута |
| `03_satellite_outages` | 79.3% | 80.8% | 82.5% | не достигнута |
| `04_link_range` | 77.5% | 62.2% | 65.1% | не достигнута |

### Основные выводы

1. Полная группировка обеспечивает связь для всех трёх северных пунктов с запасом к целевому уровню 90%.
2. Первая очередь запуска неработоспособна как самостоятельная конфигурация — 16 аппаратов в одной плоскости дают 12–27% доступности.
3. Отказ 10 аппаратов роняет сквозную доступность до 79–83%, при этом видимость остаётся высокой. Ключевой вывод: наличие спутника над пунктом не гарантирует сквозной маршрут до шлюза.
4. Ограничение ISL до 2000 км обходится дороже, чем отказ 10 аппаратов: сквозная доступность падает до 62–77%. Все потери происходят по причине `isl_disconnected`, а не из-за отсутствия видимых спутников.

## Формат выгрузки

```json
{
  "schema_version": "cosmo-A-result-1.0",
  "effective_scenario": { "...полный использованный сценарий..." },
  "routes": [
    {"t_s": 120, "client_id": "C65", "path": []},
    {"t_s": 120, "client_id": "C70", "path": ["C70", "S25", "S40", "G_MUR"]}
  ],
  "summary": { "...метрики по каждому наземному пункту..." }
}
```

Для каждого момента расчёта и каждого клиента — одна запись. `path` — от наземного пункта до шлюза. Пустой список означает отсутствие маршрута, причина указывается в поле `reason`.

## Использование расчётного модуля отдельно

`geometry.py` можно использовать независимо от сервера:

```bash
python "Расчетный модуль/geometry.py" "Данные/01_full_constellation.json" 0
```

Выведет состояние сети в нулевой момент в формате JSON.

В коде:

```python
from geometry import load, validate, snapshot, positions

scenario = load("Данные/01_full_constellation.json")
state = snapshot(scenario, t_s=3600)
```

Функция `snapshot` возвращает:

- `satellites` — координаты и флаг активности;
- `edges` — доступные связи;
- `elevation_deg` — углы возвышения по наземным пунктам.
